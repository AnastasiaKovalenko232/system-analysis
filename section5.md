# Розділ 5. User Stories у UML-нотації

Для детальної візуалізації технічної взаємодії між компонентами системи «SmartChef» побудовано діаграми послідовності (Sequence Diagrams) для двох ключових функціональних сценаріїв. Це дозволяє простежити шлях проходження запитів від інтерфейсу користувача до рівня збереження даних.

### 5.1. Сценарій «Пошук та збереження рецепта»
Цей сценарій відображає базовий цикл взаємодії користувача з каталогом страв.

**Опис логіки:**
1. Користувач вводить параметри пошуку в інтерфейсі (React), які відправляються як GET-запит до контролера бекенду.
2. Система (Node.js) виконує пошук у базі даних рецептів за вказаними критеріями.
3. Отримані результати повертаються на клієнтську частину та відображаються користувачу.
4. Користувач натискає кнопку «Зберегти», що ініціює POST-запит для оновлення таблиці `Favorites`, закріплюючи рецепт за профілем користувача.

*(Діаграма збережена у папці: screenshots/sequence_search_save)*

### 5.2. Сценарій «Генерація персоналізованого списку покупок»
Другий сценарій демонструє роботу системи з агрегацією даних для планування харчування.

**Опис логіки:**
1. Користувач обирає декілька збережених рецептів та натискає «Згенерувати список».
2. Система звертається до бази даних для отримання повного переліку інгредієнтів для обраних страв.
3. На рівні бізнес-логіки відбувається агрегація: однакові інгредієнти сумуються, а одиниці виміру приводяться до єдиного формату.
4. Сформований структурований чек-лист повертається в інтерфейс для зручного використання в магазині.

*(Діаграма збережена у папці: screenshots/sequence_shopping_list)*
